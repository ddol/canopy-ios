# Working on Canopy

Notes for anyone, person or agent, building and testing Canopy on the shared Mac. See README.md for the project and
docs/ARCHITECTURE.md for how it fits together.

## One simulator at a time

On 9 November 2026 the Mac (a 2018 Mac mini with Intel UHD 630 graphics) kernel-panicked while several iOS simulators
rendered at once: the Intel graphics driver's work queue filled up ("Submission on work queue failed due to insufficient
space", from `SimMetalHost`) and it took the whole machine down. Every booted simulator has its own `SimMetalHost`
sending work to that one small GPU. So:

- Run the tests only with `scripts/test.sh` (or `make test`). It waits for any other run from this repository (any
  checkout or worktree), shuts down every other booted simulator, tests without cloning the simulator, and shuts its
  simulator down when it ends (`CANOPY_KEEP_SIMULATOR=1` keeps it booted).
- Don't run `xcodebuild test` yourself, boot extra simulators, or give parallel agents a simulator each. Working in
  parallel is fine; running simulators in parallel is not.
- For a quick loop without a simulator, use `swift test` inside a package that builds on macOS (`CanopyModel`,
  `CanopyStore`, `CanopySync`, `CanopyReference`, `CanopyHarness`, `CanopyCapture`), or build the app without running
  it: `xcodebuild build -project Canopy.xcodeproj -scheme Canopy -destination 'generic/platform=iOS Simulator'`.
- When you boot a simulator by hand to look at the app, use one, keep its window small, and shut it down when you are
  done: `xcrun simctl shutdown all`.
- AR and LiDAR work needs a real device anyway: no simulator has scene reconstruction.

## Other things that trip runs up

- Editing files under `Packages/` while `xcodebuild test` runs aborts the run. Leave the tree alone until it ends.
- `Canopy.xcodeproj` is generated by XcodeGen from `project.yml` (`scripts/bootstrap.sh`, which the scripts run for
  you). Never edit or commit it.
- `Configs/Local.xcconfig` is git-ignored and holds per-developer settings (signing team, admin player hashes); a new
  worktree needs its own copy for device and TestFlight builds.

## Before a pull request

- `swift format lint --strict --recursive --parallel App Packages Tests` passes (`swift format format --in-place
  --recursive --parallel App Packages Tests` fixes most of it).
- `scripts/test.sh` passes. Say in the PR what was not tried on a phone.
